# TabFlow — roadmap

## Целевая функция

```
P = Throughput × Yield
```

- Простой = 0
- Убыточная операция хуже простоя
- Финансовые ошибки хуже простоя (необратимы)

**Иерархия ошибок:** финансовые потери > остановка бота > субоптимальные решения

---

## Ограничения системы

- **Витрина Ange:** 12×12 = 144 слота — жёсткий потолок Throughput
- **Win32 Input:** только один процесс владеет мышью/клавиатурой одновременно
- **Игровое время:** ~2ч вечером + ~30мин утром; разработка — весь день удалённо

## Архитектура (целевая)


**Монополия на ввод:** named mutex `PoE2Bot_InputMutex`

- Позже: mutex позволяет перекрывать фазы без гонки

## Фаза 1 — Замкнуть sell-цикл

*Цель: sell-сторона работает без ручного запуска*

**Без игры (день):**
- [x] `SoldDetector`: polling GGG API `sales_history` → сравнение с listings_index → `sold: true`

**С игрой (вечер):**
- [ ] Полный прогон в dry-run с верификацией логов
- [ ] Первый боевой прогон цикла
- [ ] Проверка остановки TradeBot при полной витрине

**Критерий перехода:** sell-цикл прошёл боевой прогон без ручного вмешательства.

## Фаза 2 — Динамическая модель ценообразования

*Цель: patience — не таймер, а целевая скорость продажи*

**Ключевая проблема текущей модели:**
- `patience = 6h/12h` — случайное приближение, не привязанное к рынку
- Аддитивная оценка ценности модов — рынок нелинеен

**Market impact:**
```
margin(volume) = sell_price(volume) - buy_price(volume)
profit = volume × margin(volume)
```
Рост объёма давит на обе стороны маржи → оптимум динамический.

**Что нужно построить (без игры — всё на данных):**
- Velocity per mod combination: из снэпшотов + sales_history → сколько часов сидит комбинация
- Детектор «уникального мода с премией»: мод, при котором цена растёт нелинейно
- Динамическая patience: функция от (fill_rate витрины, velocity комбинации, наша доля рынка)
- Порог покупки: при каком EV брать таблетку с учётом market impact

**Критерий перехода:** модель даёт корректные оценки на исторических данных; patience коррелирует с реальной скоростью продаж.

## Фаза 3 — Устойчивость цикла

*Цель: цикл не останавливается без ручного вмешательства*

**Без игры (день):**
- Все точки сбоя → catch + лог + пропуск итерации, не падение
- Автовосстановление из застрявших состояний
- Алёрт: если цикл не совершал действий N минут → звук / лог

**С игрой (вечер):**
- Намеренно провоцировать сбои: заблокированный предмет, закрытый интерфейс
- Проверить что цикл продолжает без остановки

**Критерий перехода:** цикл работал 3 вечера подряд без ручного вмешательства.

---

## Фаза 4 — Yield-оптимизация (непрерывно)

- Стратегия листинга: когда ставить выше медианы и ждать, когда в медиану
- Управление слотами: fill_rate → агрессивность переоценки
- Рефакторинг в GameHelper.Shared.dll

## Распределение времени

| Время | Что делать |
|---|---|
| День (удалённо) | Код, скрипты, модели, тесты на данных |
| Вечер (2ч) | Интеграция, боевые прогоны, новые клики |
| Утро (30мин) | Мониторинг ночного прогона, быстрые правки |

**Принцип:** игровое время — дефицит. Всё что можно проверить на данных или dry-run — не тратить на него вечер.
